- 2026-10-04: Promoting the successful isolated Blender 2.49b WASM experiment into a portable tracked recipe. The original experiment reached the actual Intro and Lv1, registered keyboard collision/death, and produced nonzero OpenAL audio. Parent owns detailed browser evidence; this is not yet exhaustive parity validation.
- 2026-10-04: Historical build lessons: host makesdna produced the wrong pointer layout; generate it with WASM instead. Global `-fcommon` crashed this LLVM build, so the one duplicate original player-stub global is an explicit extern. Binaryen's pass argument delimiter is `@`, not `=`. CPython configure must carry target facts into make's automatic reconfigure. Legacy Python callback casts need Emscripten function-pointer emulation. SDL CD-ROM support uses upstream DISABLE_SDL path; actual file audio remains OpenAL. The unknown-platform SoundSystem path silently picked upstream dummy audio until Emscripten was added to the supported platform branch.
- 2026-10-04: Graphics agent demonstrated GL4ES wireframe single-quad diagonal mismatch and provided an isolated generic renderer patch, with before/after center-pixel test. This is renderer compatibility work; game data/logic remain unchanged.
- 2026-10-04: First portable build attempted CPython `config.guess`, which that release does not bundle. Bash substitution inside a configure argument did not stop on failure; it supplied empty `--build` and configure assumed native execution. Interrupted that configuration before compile; fixed host description using a separately assigned uname-derived value, forcing cross mode. This failure illustrates why target configuration must be verified, not inferred from using emcc.
- 2026-10-04: Second portable attempt exported the host `PYTHON` selector into CPython's own configure/make, which overwrite that variable to `python`. The resulting emcc launcher error was `exec: python: not found`, and some configure feature tests were false negatives. Fixed by unsetting only `PYTHON` in the legacy build process while retaining `EMSDK_PYTHON`; regenerated configuration from scratch.
- 2026-10-04: Post-release performance investigation found Emscripten FULL_ES2 reused one temporary index buffer per size for every client-index draw. Parent's controlled Lv10 diagnostic changed only the allocator to a 128-slot ring: rendered FPS 16.4→60.1, CPU per rendering callback 8→4.4ms, key-to-next-render-end 28–72→7–20ms. Promote the exact mechanism with separate pools for each WebGL context and lazy allocation, keeping original engine/world timing untouched. Natural Intro startup retains engine-wide60Hz/maxlogic1/maxphysics1, whereas direct-scene fixtures can select different startup caps; compare like-for-like startup routes. Regression and linked-build validation are pending.
- 2026-10-04: Initial real-WebGL index-ring regression passed 3,072 indexed draws across two contexts and two size classes, but its constant index arrays could not detect stale uploads by pixel color alone. Strengthened the probe so uploaded indices choose red or green vertex triangles and change across phases; a stale index upload now produces an exact pixel mismatch. Linked candidate remains pending this stronger check. Accumulation-buffer support is deliberately not included in this candidate because the original native window may request zero accumulation bits; parent graphics agent is gathering baseline evidence first.
