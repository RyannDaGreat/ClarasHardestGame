# Exact Blender asset packaging
Create a reproducible Python3.10/Fire command that discovers Blender2.49 external assets using a pinned read-only SDNA parser, preserves the input .blend bytes, and emits 16MiB game chunks plus SHA256 delivery metadata under build/assets. Root agent integrates the browser loader and handles commits; this folder owns packaging only.

Glossary: SDNA = the structure/type information stored inside a .blend file; virtual path = the filename exposed to the engine inside the browser filesystem; delivery manifest = JSON listing downloaded files, hashes and missing original dependencies.

Design: no Blender resave or game conversion. Data discovery accepts arbitrary edited Blender2.49 files; current known paths and missing IDs must not be hardcoded into discovery. Explicit source overrides support recovered backup assets and relocated Windows paths. Ambiguous source candidates fail clearly. Missing dependencies remain visible in manifest, preserving original missing state. File chunks and external payloads are content-addressed. Browser URLs are relative to delivery manifest. No root loader changes or large tracked files.

Validation: current authoritative .blend must retain SHA256 e7f047be356346eebd166e1918ab854c9bf1494dbecd81f44174596f598a18ff, and yield exactly the seventeen virtual files and two missing original entries in .frenzy/browser-port/assets.json. Verify reassembled chunk hash, per-file bytes, source immutability and path/ambiguity behavior. Document unknown dependency classes rather than silently omit them.

Implementation specification: vendor read-only parser from dfelinto/blender-file commit9366768c4b0a22587d5c5fe0b1f74995ead1c9ae, pinned SHA2568d57232e05267fd9318a231324d0cd2040fb2e701bef4bafedd07fdccca67369. package_assets.py uses Fire0.6.0 and Python3.10+. Discover image/sound/font paths directly in each input. Packed payloads stay inside .blend. Reject linked libraries, sequencer media, image sequences and external game-load actuators until transitive discovery is implemented; arbitrary Python file access must be declared through extra_files. No basename guessing. Config maps old absolute path prefixes and exact virtual paths to local inputs, names explicitly allowed missing IDs/paths, and can add extra_files. Unknown missing files fail before publishing a delivery manifest; known originals remain listed. Content-addressed chunks may accumulate across runs; stale chunks are harmless and never referenced. Reuse a chunk only after hash/size verification. Reject individual external files over GitHub's100MiB file limit. Manifest publication is atomic. Input .blend stat and SHA256 are checked before/after packaging to detect concurrent editing.

Verification implementation: verify_pack.py independently rereads every generated payload, joins the game hashes incrementally, compares all external path/hash/size records to the prior browser fixture, checks deterministic second packaging, and mutates only a temporary COPY of the .blend to prove path discovery is fresh and missing added assets fail. Combined original stream SHA256 must match the prepackaging hash before manifest publication.
